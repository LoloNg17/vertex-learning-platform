

- Run initialization from the repository root.

  - show compact Sign In and Sign Up actions when signed out;

- Keep the notification bell presentational.
- Do not add custom authentication pages unless the current Clerk setup explicitly requires them.
- Do not install `@clerk/ui`, because this repository has no `components.json`.
- Do not read, print, log, expose, or manually inspect real environment secret values.
- Allow the Clerk CLI to write the required local development environment variables.
- Add or update `.env.example` only with variable names and blank/example-safe placeholder values.
- Never put real Clerk credentials in `.env.example`.
- If `.gitignore` currently ignores `.env.example`, add only the narrow exception required to track `.env.example`.

- Never put `CLERK_SECRET_KEY` in a `NEXT_PUBLIC_*` variable.
- Only the Clerk publishable key may be browser-visible where required.
- Never print, echo, inspect, or commit `.env.local` values or any real credential.
- Do not commit Clerk secret material.
- Use Clerk middleware on the server and preserve Next.js server/client boundaries.
- Do not mark routes private without an explicit product requirement.
- Authentication availability and authorization are separate concerns.
- Public browsing must remain public.
- Review all files generated or modified by the Clerk CLI before retaining them.
- Do not weaken existing security boundaries to make Clerk integration easier.
